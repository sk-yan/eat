# 下班厨房

食材选择、网上找菜与全家共享菜谱。React、TypeScript、Vite 和 Node/Express，适配电脑和手机。

- 选择肉类、蔬菜，筛选现有食材、厨具、用时与带饭菜。
- 17道带来源的备餐做法，支持原站在线搜索和收藏。
- 家人可以添加、编辑菜谱和成品照片，移除后可撤销。
- 全家菜谱保存在服务器；库存与收藏保存在各自浏览器，不自动扣库存。

## 一周食谱网页版

独立周食谱入口面向 GitHub Pages：每日早餐与加餐、14顿午晚餐、逐餐热量和P/F/C、个人BMR/TDEE与训练消耗计算、周末备餐清单、用量汇总，以及整周打印版。低碳高蛋白修订版日均估算约1762kcal、P164g、F68g、C122g，包含三顿牛肉、两顿三文鱼、两顿虾、三顿鸡腿和四顿鸡胸主菜。所需蛋白质全部放进早餐和午晚餐，不设独立蛋白粉加餐。

计算器参考 NutriFit Planner 的Mifflin-St Jeor、600kcal缺口、蛋白质2.0g/kg和脂肪35%方案，但把非运动日常活动与净运动消耗分开，避免重复计算训练。年龄、性别、身高、体重和训练信息没有写入代码，用户填写后只保存在当前浏览器。营养值按通用食物成分估算，实际以包装营养表、肉类肥瘦和可食重量为准。

```sh
npm run build:pages
npm run preview:pages
```

构建输出 `dist-pages/`，按仓库子路径 `/eat/` 生成静态资源。仓库 Settings → Pages → Source 设为 GitHub Actions 后，`Publish Weekly Menu` 工作流发布到 `https://sk-yan.github.io/eat/`，是否已上线以部署工作流结果为准。备餐勾选只保存于各自浏览器。

**GitHub Pages 目前只发布周食谱，不运行完整应用的在线搜索或家庭共享写入接口。** 完整应用仍使用下方 Node 服务运行方式，已有功能没有被替换。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 运行

需要 Node.js 22.12 或更高版本，已在 Node 26 本地验证。先安装依赖，然后运行：

```sh
npm ci
npm run build
npm start
```

开发模式：`npm run dev`。默认监听 `127.0.0.1:5173`，占用时自动尝试接下来的19个端口；显式设置 `PORT` 时不自动换端口。终端和 `.runtime/server.json` 显示实际地址。需要常驻时可运行 `node scripts/start-background.mjs`；它启动已构建的版本，将日志写入 `.runtime/server.log`。

测试：`npm test`，构建和类型检查：`npm run build`。

## 给家人使用

本地地址 `127.0.0.1` 只能在启动服务的电脑上访问。后续上线需要运行 Node 服务，并将 `FAMILY_DATA_DIR` 挂载到持久磁盘；不要只上传 `dist`，也不要依赖免费服务的临时文件系统保存家人的菜谱。

仓库附有可选的 `Dockerfile`，没有开通或绑定任何收费服务。单实例运行，不能让多个进程同时写同一份 JSON 数据。线上需要 HTTPS 和反向代理。

配置可参考 `.env.example`，在服务器创建不入库的 `.env`；`npm start` / `npm run dev` 自动读取。线上必需设置：

| 变量                  | 作用                                                            |
| --------------------- | --------------------------------------------------------------- |
| `HOST=0.0.0.0`        | 允许外部连接                                                    |
| `NODE_ENV=production` | 关闭本地免口令写入                                              |
| `PORT`                | 主机指定的监听端口                                              |
| `FAMILY_CODE`         | 全家共用的编辑口令，至少8字符，建议长一些且不要复用其他账号密码 |
| `FAMILY_DATA_DIR`     | 持久磁盘目录，保存 `recipes.json` 与 `images/`                  |
| `TRUST_PROXY=1`       | 仅在恰有一层可信反向代理且应用端口不能被绕过直连时设置          |

家庭口令只保护添加、修改和移除，**不保护浏览**：任何获得线上网址的人都可以查看菜谱与照片。不要上传住址、人脸、证件或其他隐私照片。照片通过浏览器缩放后保存；有共享口令的家人都能修改全家的菜谱。登录有效期最多30天，服务重启后需要重新输入口令。

无口令的默认开发模式仅限本机使用。线上未配置口令时，写入会被拒绝，不会变成任何人可写。

### 备份与恢复

定期备份整个 `FAMILY_DATA_DIR`，包括 `recipes.json` 和 `images/`，不要提交到 GitHub。停服后备份或使用主机的磁盘快照，恢复时保持目录结构和运行用户的读写权限。移除是软删除，照片也会保留，需管理员备份后定期整理；磁盘不是无限的。

家人新增菜谱在刷新页面或约30秒自动刷新后出现。库存和收藏只属于当前浏览器，不跨设备同步；全家菜谱跨设备共享。

## GitHub 校验

`.github/workflows/check.yml` 会在推送和 Pull Request 时安装依赖、运行测试和两种构建。`.github/workflows/pages.yml` 只发布静态周食谱。家庭上传照片、运行数据、日志、依赖和 `.env` 已在 `.gitignore` 排除。

## 数据与能力边界

- 备餐做法是人工整理的单人份改写，原作者链接与配图来源保存在 `data/sources.json`，不展示虚构热量或减脂承诺。
- 网上菜谱由服务端实际请求下厨房公开搜索页。结果缓存10分钟，页面标明缓存和检索时间。食材匹配在预览中依据标题，打开详情后再获取原站食材清单。原站完整步骤通过链接查看，不整篇复制。
- 网上结果标题默认排除豆腐、燕麦和明显内脏菜名，符合本次用户偏好；标题未提及的配料仍可能出现在原站用料中，查看详情核对。修改偏好时可调整服务端过滤词。
- 第三方网站可能超时、验证或改版；失败时显示真实错误，仍可使用本地备餐做法或打开原站。未绕过验证码或登录限制。
- 食材名称是唯一在线查询参数，不传送健康史、库存重量或会员信息；无 API 密钥。详情 URL 限定下厨房菜谱路径，图片限定其公开 CDN。
- 主料匹配不代表调料齐全或库存足量。详情中调料为每份参考，主料份数可调整，烹调时长不随份数线性增加。
- 冷冻蓝莓、带骨鸡腿和高压锅的做法需结合食品包装、实际中心温度和设备说明；这些菜谱不是治疗或营养处方。

## 文件

- `src/`：界面、样式与交互。
- `shared/ingredients.mjs`：默认库存与别名。
- `shared/weekly-plan.mjs`：确认版周菜单、早餐替换与汇总数据。
- `src/WeekPlan.tsx`：完整应用与静态入口共用的周食谱。
- `shared/matching.mjs`：匹配、筛选、查询校验。
- `server/source.mjs`：公开菜谱来源解析，禁止任意 URL 抓取。
- `server/family.mjs`：家庭口令、菜谱持久化、照片和软删除。
- `server/catalog.mjs`：备餐改写。
- `scripts/collect-sources.mjs`：源链接与配图采集。重新采集可指定来源键，例如 `node scripts/collect-sources.mjs yogurt`；站点改版时应复核配图与标题。

主料、步骤、照片必须与来源定位相符；外部作者文章中的宣传性健康说法不作为本应用的事实。
